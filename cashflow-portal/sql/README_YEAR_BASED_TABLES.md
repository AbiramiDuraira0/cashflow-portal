# Year-Based Expense Tables Documentation

## Overview
Due to Supabase free tier limitation of **1000 records per table**, the expense data is partitioned into **year-based tables**.

## Database Structure

### Tables Created
- `expense_2021` - Holds all expenses for year 2021
- `expense_2022` - Holds all expenses for year 2022
- `expense_2023` - Holds all expenses for year 2023
- `expense_2024` - Holds all expenses for year 2024
- `expense_2025` - Holds all expenses for year 2025
- `expense_2026` - Holds all expenses for year 2026 (renamed from original `expense` table)

### Table Schema
Each table has identical structure:

```sql
CREATE TABLE expense_YYYY (
    expense_id        INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    month             VARCHAR(20) NOT NULL,
    year              INTEGER NOT NULL DEFAULT YYYY,
    category_id       INTEGER NOT NULL,
    category_name     VARCHAR(50) NOT NULL,
    category_icon     VARCHAR(10),
    sub_category      VARCHAR(100),
    subcategory_icon  VARCHAR(10),
    amount_inr        DECIMAL(12, 2) NOT NULL CHECK (amount_inr >= 0),
    notes             TEXT,
    is_delete         BOOLEAN NOT NULL DEFAULT FALSE,
    created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    CONSTRAINT chk_expense_YYYY_year CHECK (year = YYYY)
);
```

### Indexes
Each table has 3 indexes for performance:
- `idx_expense_YYYY_year_month` - On (year, month) for fast date filtering
- `idx_expense_YYYY_category` - On (category_name) for category grouping
- `idx_expense_YYYY_is_delete` - On (is_delete) for soft delete filtering

### Triggers
Each table has auto-update trigger:
- `trg_expense_YYYY_updated_at` - Automatically updates `updated_at` timestamp on record update

## Service Layer Implementation

### File: `src/app/services/expense.service.ts`

#### Helper Method
```typescript
private getTableNameForYear(year: number): string {
  if (year >= 2021 && year <= 2026) {
    return `expense_${year}`;
  }
  console.warn(`⚠️ Year ${year} outside supported range (2021-2026). Using expense_2026.`);
  return 'expense_2026';
}
```

#### Load Data (All Years)
```typescript
async loadExpenseData(): Promise<void> {
  // Queries all year tables (2021-2026)
  const years = [2021, 2022, 2023, 2024, 2025, 2026];
  const allEntries: ExpenseEntry[] = [];

  for (const year of years) {
    const tableName = this.getTableNameForYear(year);
    const { data, error } = await this.supabase.db
      .from(tableName)
      .select('*')
      .eq('is_delete', false)
      .order('year', { ascending: false })
      .order('month', { ascending: false });
    
    if (data && data.length > 0) {
      allEntries.push(...data.map(this.transformDbToApp.bind(this)));
    }
  }
  
  this.expenseData.set(allEntries);
}
```

## Benefits

✅ **Scalability:** Each table can hold up to 1000 records  
✅ **Performance:** Smaller tables = faster queries  
✅ **Free Tier Compatible:** Stays within Supabase limitations  
✅ **Easy Maintenance:** Clear data separation by year  
✅ **Automatic Routing:** Service layer handles table selection

## Limitations

⚠️ **Year Range:** Currently supports years 2021-2026 only  
⚠️ **No Cross-Year Queries:** Cannot easily aggregate across multiple years in single query  
⚠️ **Table Management:** Need to create new tables for future years manually

## Troubleshooting

### Issue: Table not found
**Solution:** Execute SQL scripts in order (005 then 006)

### Issue: Year constraint violation
**Solution:** Ensure year in form matches table's year constraint

### Issue: Record not found on update/delete
**Solution:** Verify record exists in correct year table

### Issue: Duplicate IDs across tables
**Solution:** Normal behavior - each table has its own sequence. IDs are unique within table, not globally.
